Components

The manager's API

One request, one reply, on D-Bus (org.privateai.Manager1) or the named pipe (u32 length, JSON, 1 MiB); the caller is the OS identity of the connection. A <Method>As form names a signed-in user; the manager answers it only to the bff's account and only for a current member of pai, re-checked at each call.

GroupMethodsWho
ReadsListInstances, Status, BootEnabled, ServerProfiles, ReadFile, Devices, Versionthe listing and states to anybody; files and devices by right (control asked quietly for Devices)
RunStart, Stop, Restartcontrol
WritesWriteFile, WriteFileIf, SetBootEnabled, SetModelProfile, SetServerProfile, SetInstanceTags, CreateInstance, RemoveInstance, CreateServerProfile, DeleteServerProfileconfigure: a pai member (Linux: polkit, own password)
bff onlyAuthenticate and every <Method>Asthe bff's account (uid on Linux, service SID on Windows)
Planned (13d)Metrics, MetricsHistory, ReadLog and their As formsproposed: control for metrics, pai for logs

The bff's routes

Only /, /assets/* and the three session routes answer without a session; every other route is 401 session-required without one. Errors are {key, args}.

GroupRoutes

NodeGET /api/version, GET /api/node, GET /api/node/devices
InstancesGET|POST /api/instances, DELETE /api/instances/{id}, POST .../{id}/start|stop|restart, GET|PUT .../{id}/boot, GET|PUT .../{id}/server, PUT .../{id}/tags
Server profilesGET|POST /api/profiles/server, GET|PUT|DELETE /api/profiles/server/{id}
Model profilesGET /api/profiles/model, GET|PUT /api/profiles/model/{id}, PUT .../{id}/enabled
AssociationsPUT /api/instances/{id}/profiles/server, GET|PUT /api/instances/{id}/profiles/model, PUT .../model/{profile}

What is planned

  • 13c Strata: a second engine run and configured by the manager.
  • 13d monitoring (proposed): the live hardware view, history and on-demand log reads, through new manager methods and bff routes.
  • Item 14, the router: one OpenAI-compatible endpoint in the bff that sends each request to the instance serving the model, logging every request.
  • Step 14, the super-manager: nodes governed over mutual TLS with the manager protocol unchanged; the bff in hub mode.
