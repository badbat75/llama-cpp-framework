# docs\

- `amd_ai_pro_r9700.md`, `nvidia_rtx4070_super.md`: per-GPU configuration reference guides: the measured optimum per llama.cpp/server/preset parameter on that card, the evidence, options that measured worse than they look, and a `TBD` table for parameters not yet measured. Terse: a reference, not a narrative. Each guide covers ITS card only: no machine-specific device ids (`ROCm1`, `CUDA0`), no split vector of one pairing, no mention of the other card. Every value traces to a measurement; a value recorded in `benchmarks\bench.db` names its campaign, as in (campaign `27b-kv-f16-20261016`) (`llama-cpp-config bench query campaigns --db benchmarks\bench.db` lists them), never a local archive file or path; no absolute paths; when a campaign changes a result, update the row (and fill or retire its placeholder) in the same change.
- `qwen3.8_flash_next.md`: per-model reference for Qwen3.8-Flash-Next (`qwen4exp`) in the same spirit: measured values with their evidence, a `TBD` table for the rest. It names the card it was measured on but stays about the model.
- `qwen3.8_27b.md`: the same for Qwen3.8-27B (`qwen35`, dense, embedded MTP head), on both cards in one model; per-card detail stays in the card guides, which it cites.
- `build-pipeline.md`: developer reference for the root-level build scripts and build conventions (not a GPU guide; the rules above do not apply to it).
