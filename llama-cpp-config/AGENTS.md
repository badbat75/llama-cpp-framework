# llama-cpp-config\

Rust GUI + CLI configurator; five tabs:

- **Server** → `server.ini`.
- **Models** → `presets.ini` (an on/off switch per preset MOVES its section, verbatim, to `presets.ini.disabled`, which llama-server never reads; only the Models tab and the CLI's `preset` commands see both files: `presets.rs` module header). New… has a second source, **From Hugging Face…** (`gui\hf_dialog.rs` over `hf.rs`, the same backend as `preset download`): search GGUF repos by name (each row: `org/repo`, downloads, `MoE`/`dense` and size when known, quantizations) or type one, list a repo's quantizations (each with its placement on this machine, read from its remote GGUF header by `hf_fit.rs`, modelled CARD BY CARD in split order with the `tensor-split` it would write, and one marked recommended), pick one and its sidecars, and Download closes the modal and hands the job to the background (`gui\downloads.rs`: the transfer, then the preset derived off the event loop, shown in the separate Downloads window, opened from the footer indicator, the dialog's Downloads button or the tray's Open downloads); the preset is created by `hf::save_preset` and the list reloads WITHOUT selecting it (the row's Show preset does, through the discard guard), with that placement as keys (`hf_fit::placement`: `device`, `tensor-split`, `n-cpu-moe`, `n-gpu-layers`, `ctx-size`, a drafter's `device-draft`, the encoder's `mmproj-device` / `mmproj-offload = false`; nothing on a one-card machine the model fits; the estimate counts the mmproj and the separate drafter as currently ticked/picked, on the card each lands on, and the tick and the pill re-estimate every row: `hf_fit` header, "The extras") and a `; placement =` comment saying it is an estimate to tune (`Preset::placement_note`, a comment like `project_url`, shown on the GPU distribution card with a Clear button). Delete can take the preset's model files with it (`linked_files.rs`, driven by `models_tab::DeleteDialog` and by `preset delete --delete-files`): every tick starts cleared, a file another preset references in EITHER INI file cannot be ticked (the CLI refuses it unless `--even-if-shared`), the section is removed before any file, a failed file delete is reported and never blocks the rest, and the only folders removed are EMPTY ones between the file and its `models` / `mmprojs` / `mtps` / `dflashs` subfolder (`remove_empty_dirs`: never the subfolder, never outside `ModelsDir`, never through a link). Keep those bounds when touching it: it is the one code path that deletes user files.
- **Benchmark** → measure or compare presets into `%LOCALAPPDATA%\llama.cpp\bench\bench.db`, or the database `settings.ini` `BenchDb` names (`db::work_path`; e.g. a clone's `benchmarks/bench.db`) (`bench\db.rs`: the repo's `benchmarks\schema.sql` compiled in, one campaign per tab run or sweep, a run written in ONE transaction only when its preset finished, never a failed or cancelled one; `bench\record.rs` holds it in memory meanwhile; `bench\host.rs` detects machine and software, the ROCm/CUDA/Vulkan SDK dist versions coming from `build.rs` via `LLAMA_FW_*`; `bench\query.rs` is `bench query`/`answer`/`publish`; secrets are dropped and absolute paths cut to file names ON THE WAY IN (`public_value` for a value, `public_text` for logs, notes and reports), since the database may be the public one; the machine row is matched by a fingerprint over a canonical text, never by id) (the live engine's prompt is a FILE, see below; its unattended half is the CLI's `bench sweep`, which runs the engines once per value of ONE presets.ini key, records each finished leg as a run of one bench.db campaign with the digest as its report, and restores the key (a `sweep-pending-<stamp>.json` marker holds the value to restore until it is back); a live leg RESTARTS llama-server since the key rides the child's launch args; `;` separates values because `device`/`tensor-split` contain commas).
- **Integrations** → `opencode.json` model list (every ENABLED preset; once Save has created the provider, every preset change and server.ini save rewrites it: `integrations.rs` module header; a model whose context the fit sizes at load time gets no `limit`, see the `--parallel` footgun) + Claude Code snippet.
- **Settings** → the configurator's own preferences.

Plus llama-server run controls, the View-logs window, the Downloads window (`gui\downloads.rs` + `ui\downloads_window.slint`: one card per Hugging Face download, its progress, state, Cancel / Resume / Show preset / Dismiss) and the HW Monitor window (`hwmon.rs` + `gui\hw_window.rs`: live bars for every GPU, CPU, memory and the models directory's disk; the sampler is per OS, `hwmon\linux.rs` and `hwmon\windows.rs`, and a bar added to one should be weighed for the other). Architecture, per-tab walkthrough, UI-binding conventions, source layout and test topology live in [README.md](README.md), and every module has a `//!` header; read those first. The crate has zero Clippy warnings; it uses `#[cfg]` compile-time branching for OS portability in `paths.rs`, `gui.rs`, `runstate.rs`, `main.rs`, `gguf\ffi.rs`, and `proc.rs` (the shared `CREATE_NO_WINDOW` process launcher used by `devices.rs` / `server_version.rs` / `runstate.rs`); `single_instance.rs` is Windows-only wholesale. `cargo test` links only thanks to the `/force:multiple` rustflag in the generated `.cargo\config.toml` (see [docs\build-pipeline.md](../docs/build-pipeline.md), lld).

## Common changes

The two recurring recipes live as authoritative checklists at the top of the module they start in; follow those, not a from-memory list:

- **Adding a per-model preset field** fans out to 7 places (kebab-case INI key ↔ snake_case Rust field; INI schema → form struct → widget → conversions). Checklist: top of `src\presets.rs`. Trace an existing field like `ctx-size` as the template.
- **Adding a server (server.ini) field** is the same shape plus **three spots in `cli.rs`** (the server has a per-field `set`; the preset CLI is list/show/delete/enable/disable, with no per-field `set`) plus **`runstate::server_args`** (the launch/Command-Line leg). Checklist: top of `src\server_cfg.rs`.

Cross-cutting rules the recipes rely on:

- **Before adding a new property, field, or function, search the codebase for existing ones that already cover the case** (e.g. `base_url_default` on `ServerForm` already tracks whether the Base URL was user-specified; a duplicate `chat_url_specified` on `AppState` was a mistake). Grep first, then decide if something genuinely new is needed.
- **Model Info rows show facts, not explanations.** No trailing hints like "saves VRAM (slower)" or "`--reasoning on|off` switches it". The doc comments (`///`) explain the why; the displayed value is just the fact.
- **`open_chat_url` prefers Base URL custom over launch URL.** `state.slint` derives it from `chat_url` when `server_form.base_url_default` is false (custom Base URL), otherwise from `launched_url`, falling back to `chat_url`. The form's `base_url_default` field is the single source of truth: no duplicate property needed. Whether there is a chat page at all (`Webui`, `--no-ui`) follows the same two sources, never the form: `chat_ui_enabled` reads `launched_ui` while the GUI's launch is pinned, else `chat_ui_saved`; `can_open_chat` gates the rail button, and the tray (no `AppState`) gets a copy through `gui::push_tray_status`.
- **Model info names only files the preset LOADS.** `draft_line()` reports the model's own MTP heads plus the preset's `--model-draft` ("draft file: x.gguf", whose header is the "Draft file" row below), and "none" when there is neither, never a blank. Do not reintroduce a "best match" drafter line based on file names: it reads as a claim the drafter is in use, and a name-token match offers drafters built for a different fine-tune. Choosing a drafter belongs to the Assets picker.
- Editable widgets bind **two-way** (`<=>`) to `AppState.…`; a one-way binding goes stale after the first edit. The sanctioned one-way exceptions (read-only displays, `for`-row widgets, `MappedComboBox`, the Slider/AutoSlider push, `SegmentedControl`) are catalogued in the README's conventions section.
- Nearly every step is guarded by a test that fails when skipped: INI and form round-trips (`presets.rs` / `form.rs`; `server_cfg.rs` / `server_form.rs`), the CLI leg's exhaustive-struct tests (`cli.rs`), the launch-arg leg (`runstate.rs`), widget-binding staleness (`src\tests\ui_bindings.rs`: one widget PER KIND, plus the one-way-binding text lint `src\tests\binding_lint.rs`) and the Models/Integrations callback funnel (`src\tests\save_flow.rs`). The unguarded remainder: forgetting the widget entirely (the field never appears in the UI), and skipping the path-field `validate_for_save` step (a `;`/`#` path then saves fine and reloads truncated; see the checklists' final step).
- Run the e2e tests with `cargo test` (debug profile), **not** `--release`: they need Slint element debug info that `build.rs` emits for non-release builds only. Bare `cargo test` is the right command: the generated `.cargo\config.toml` already caps both thread pools at `BuildJobs`. Full test-topology rationale (single shared `#[test]`, `LLAMA_CPP_CONFIG_DATA_ROOT` redirect, `src\tests\` vs `tests\`): README "Tests" section.

## Footguns

Recurring traps, each with a canonical write-up in the code:

- **On Wayland a window that was never shown still exists** (`gui.rs` `discard_unshown_wayland_window`): Slint's winit backend creates the native window of every component when the event loop starts, and Wayland has no hidden windows, so a tray-only launch (`gui --minimized`) and the always-hidden log window were toplevels the compositor knew about, and GNOME's dock listed the app as running. `hide()` alone is a no-op on a window never shown; the helper waits for the native window, then calls `show()` + `hide()` in one event-loop turn (the backend destroys a Wayland window on hide), before any frame is drawn. Any new window that starts hidden needs the same call. The tray icon has such a window too (`AppTray` is a root, so the backend builds one for it; it showed in GNOME's Alt+Tab as an empty "Slint Window"), and no `window()` to call the helper on: `DiscardTrayWindow`, a winit application handler installed before the first component, does the same show + hide on the first event that window receives, recognizing it by the backend's default title: the program's name since Slint 1.18 (`default_window_title`, mirroring i-slint-core's `application_name`; "Slint Window" before, and a Slint upgrade that changes it again brings the ghost back). So every real window must set a `title`. Related: `slint::set_xdg_app_id("llama-cpp-config")` must run AFTER the first component is built (it fails with no platform) and names the desktop entry the deb/rpm install, which is how the dock finds the icon instead of a generic gear. Check either with `WAYLAND_DEBUG=1`: `get_toplevel`, `set_app_id`, `xdg_toplevel.destroy`.
- **`--mlock` / `--no-mmap` are ONE enum, `-lm`/`--load-mode`**, a per-preset key (`presets.rs` `load_mode`, canonicalized by `server_cfg::normalize_load_mode`; blank = llama.cpp's `auto`): the old flags are removed upstream (a launch line carrying one fails to parse and nothing starts). The modes do not compose like two bools: `mlock` alone is mlock **without** mmap (`use_mmap` is true only for `mmap`/`mmap+mlock`/`auto`, `llama-model-loader.cpp`). Hence one dropdown. It used to be server.ini `LoadMode`, always on the router's command line and so shadowing every preset; the router line now carries no `-lm`, `--split-mode` or vision-device setting, and nothing in the binary migrates an old `server.ini` (its `LoadMode`/`Mlock`/`NoMmap`/`SplitMode`/`MmprojDevice` keys are ignored).
- **GPU placement is a table, not two text fields** (`gpu_split.rs` + `GpuSplitTable`, Models tab only: `device`, `tensor-split`, `split-mode` and `override-tensor` are per-preset keys, because server-wide they rode the router's CLI and shadowed every preset's, so server.ini has no GPU distribution): `--tensor-split` is positional over `--device`, so neither means anything alone. A blank tensor-split over 2+ GPUs = split by *free VRAM*, not evenly. The vector is **normalized** over `n_layer_all + 1` positions (every block plus the **output layer**), so on a 33-block model 83/84/85% are one launch. Hence `Layout`/`block_counts`: where the model is known the column is edited in **blocks**, and since a vector summing to the positions assigns exactly itself, writing counts back is the identity (`29,5` *is* blocks 0-28 / 29-32+output). A count cannot be edited alone (rows absorb from the back), so the cell is a **`Slider`** committing on `released` (`SpinBox` is banned for stray wheel events; the accessibility set-value action raises `changed` without `released`). The INI still stores the **ratio**, re-derived per model, so re-pointing a preset rescales it.
  - The `--split-mode` combo sits ABOVE the table, and the columns follow it. `layer`: blocks. `row`: the raw ratio (matrix bytes follow row fractions; CUDA/ROCm only, Vulkan silently falls back to the layer cut, KV follows the layer cut); deprecated upstream in favour of `tensor` but still parses, so listed last and labelled. `tensor` (experimental tensor parallelism): the same raw ratio, the checked devices become ONE meta device and every weight AND the KV cache are cut by that vector; a blank vector is an EVEN cut there. `none`: llama.cpp keeps only `devices[main_gpu]`, so the head row reads 100%, other checked rows "unused", and the drag handle is the only control left. A strip under the combo (`preset_split_mode_warning`) names `tensor`'s launch-time refusals: an arch on `llm_arch_supports_sm_tensor`'s deny-list (mirrored in `gguf::arch_supports_sm_tensor`, re-check on a llama.cpp bump), `flash-attn = off` (`auto` is promoted), and NO device pinned (it then pools every detected device, duplicate Vulkan views and iGPU included); `--fit` is merely skipped, so `ctx-size` is the user's to size. The single "layer (default)" entry merges default/layer (same launch everywhere).
- **A hand-set split with the context left to the fit can over-fill ONE card** (`hf_fit.rs` header, "The placement"; `common/fit.cpp`): the fit shrinks an unset context against the free memory of ALL devices together, and only then gives up on a set `tensor-split`, `n-gpu-layers` or tensor override (`n-cpu-moe` expands into one), keeping the cut. So a derived placement always writes `ctx-size` with any of those (the estimate's own 32k), which also turns `fit` off (`form::fit_allowed`). Never write such a split with `ctx-size` unset; only a bare `device` (the model on one card) is left to the fit. And a placement is modelled per card, never as one pool: a block never straddles two cards, so two cards hold less than their sum, and the small card bounds its share.
- **"All layers offloaded" still leaves the embedding table in PINNED HOST RAM** (`tensor_override.rs` + `TensorOverrideTable`): `token_embd.weight` stays in a host buffer, pinned with a GPU backend active (`ROCm_Host`/`CUDA_Host`), which Windows reports as **Shared GPU memory**. The cure is an `override-tensor` rule (`^token_embd\.weight=ROCm0`); the value is split on `,` and at the first `=` before parsing and cannot be escaped, hence a table.
- **A tensor-placement regex is matched ANYWHERE in the name, and the first matching rule wins** (`tensor_override.rs` `KINDS`, `tensor_picker.rs`): `output\.weight` also takes every `blk.N.attn_output.weight` and `token_embd\.weight` takes `per_layer_token_embd.weight`, so the families outside the blocks are anchored with `^`, and everything the picker writes ends in `$`. The picker and the coverage lines match with the `regex` crate, which agrees with llama.cpp's `std::regex` (ECMAScript) on what the table writes but not on every hand-written form (no lookaround or backreferences): a regex it cannot read opens the picker unticked and says so, never guesses. `compile` checks its output against the tensor list before returning it; keep that check, it is what makes a tick mean exactly that tensor.
- **…but that cure is CONDITIONAL, and violating either condition costs 10x** (`gguf.rs` `embd_line` / `embd_pin_warning`, surfaced as Model info → **Embeddings** + a warning strip): (1) `token_embd`'s **own** quant must have a GPU `get_rows` kernel (`ggml-cuda.cu` `supports_op`), or the lookup round-trips to the host every token (measured 25 → **2.8 tok/s**; prefill untouched; GPU engines read 0%, so it looks *idle*, not slow). Today every K- and IQ-quant has one (IQ4_NL/MXFP4 only for widths that are multiples of 256; Vulkan's set is a superset, so the mirror errs toward a needless warning there); what still trips the warning is Q8_1, Q8_K, TQ1_0/TQ2_0 and NVFP4. The file NAME does not tell you the type (Unsloth's `Q6_K_XL` keeps `token_embd` at Q8_0 while `Q4_K_XL`/`Q5_K_XL` drop it), so the row reads the header. (2) The card needs **room**: pinning MOVES the table into VRAM (~1.26 GiB at Q8_0), which can tip a full card into paging (23 → **13.7 tok/s**). Prefer the **per-preset** scope. `gpu_has_get_rows` mirrors the upstream switch and must be diffed against CURRENT upstream source on every bump: a missing type costs a needless warning, a type listed *without* a kernel green-lights the pin this exists to prevent.
- **The image encoder is placed on its own** (`presets.rs` `mmproj_device`, the Models tab's "Vision GPU"): it defaults to the FIRST entry of `--device` (a preset's `device` key counts; `--device none` keeps it on CPU), falling back to the first GPU backend when no device is pinned. The per-preset `mmproj-device` key (`-mmdev`) overrides both defaults. `hf_fit` mirrors this rule when it counts the encoder (`estimate_with`'s `Spot::Gpu { pinned }`): a change of the default device order there or upstream changes which placements need the key.
- **Preserving past thinking is ONE flag, not a template kwarg** (`presets.rs` `reasoning_preserve` + the README): `--reasoning-preserve` sets `preserve_reasoning`, which `caps_apply_preserve_reasoning` (`common/jinja/caps.cpp`) expands into THREE template variables (`preserve_thinking`, `clear_thinking`, `truncate_history_thinking`) because templates disagree on which they read. Hand-writing one into `chat-template-kwargs` is a **silent no-op** on templates reading another, and never registers with the capability probe. "Supported" only means the trace showed up in the probe's render: a template that preserves *unconditionally* (Ornith-1.0) reads as supported while gating on nothing. Upstream defaults it ON: the tri-state's `default` (`None`, pass nothing) means ON on every supporting template, `off` (`--no-reasoning-preserve`) is the one value that changes anything, and a hand-written `preserve_reasoning` kwarg draws a DEPRECATED warning.
- **`--parallel` DIVIDES the context, and omitting it is not "1 slot"** (`integrations.rs` `effective_ctx`, surfaced as each opencode model's `limit.context`): `n_ctx_seq = n_ctx / n_parallel` (`llama-context.cpp`), so `parallel = 2` halves it, **unless the key is absent**: the default `-1` = auto picks 4 slots *and a unified KV cache*, under which every slot sees the whole `n_ctx`. And `ctx-size` absent means the model's **trained** context. Publishing 256k for a 256k model that pins `parallel = 2` promises a context llama-server rejects at 128k+. **And with the fit on and the context automatic there is NO number to publish** (`integrations.rs` `fit_may_cut_ctx`, the single rule `advertised` applies): the fit cuts the context at load time to fit free memory, so such a model gets no `limit` in `opencode.json` and no context lines in the Claude Code snippet. The rule reads the RAW `fit` key (`fit_on`: absent = upstream's ON, `[*]` cascades), not `Preset::fit`, which reads an absent key as off; `split-mode tensor`, a `kv-unified-per-slot`-sized pool and `ctx-size = 0` (unless a `fit-ctx` overwrites its sentinel) are exempt.
- **Thinking support is read from the template's SOURCE, and the verdict is about the TEMPLATE** (`gguf.rs` `Thinking` / `thinking_line` / `past_thinking_line`, Model info → **Thinking** + **Past thinking**): there is no Jinja engine here, so the scan looks for the names the flags act on (`enable_thinking` for `--reasoning`; `preserve_thinking`/`clear_thinking`/`truncate_history_thinking` for `--reasoning-preserve`): a `yes` is a fact, a `no` only "no marker this build knows" (MiMo-VL's template names nothing yet the model thinks). **Past thinking** tells what llama-server's log cannot: its probe prints `supports preserving reasoning` both for a template that gates on the flag and for one that preserves unconditionally.
- **The FOLDER a drafter sits in does not say which speculator it needs** (`gguf.rs` `draft_spec_type`, applied in `gui\models_tab.rs`'s `draft_picked` handler): `mtps\` and `dflashs\` share one dropdown, and `draft-dflash` vs `draft-dspark` share arch, name shape and folder, told apart only by a `markov_w1.weight` tensor INSIDE the file. The wrong one does not fail: `is_dspark` changes the drafting batch layout (`common/speculative.cpp`), so every draft is rejected: speculation that costs and never pays. Hence the picked FILE's header decides, mirroring `common_speculative_types_from_gguf`. The framework still WRITES the key (shows the verdict before launch, works on older builds). The folder guess is the FALLBACK: a separate MTP head with `block_count = 0` (gemma4-assistant) matches no rule, and an unreadable GGUF is not evidence.
- **Draft placement needs a draft FILE** (`presets.rs` field docs): `--device-draft` / `--n-gpu-layers-draft` are read only inside `if (has_dft())`. With MTP heads embedded in the main GGUF, the draft context runs on the target's device, ignoring both. With a SEPARATE head file they apply: pin model **and** draft to one device, or leave the draft on CPU (multi-device "auto" fitting crashes those heads). An EMPTY `--device-draft` inherits the model's `--device` list (`common_base_params_to_speculative`), and a draft on exactly one device is forced to the layer split even under an inherited `--split-mode tensor`.
- **BF16/F16 on gfx1201 can die inside hipBLASLt, and the knob is an env var no llama.cpp flag can reach** (`server_cfg.rs` `rocblas_use_hipblaslt` → `runstate.rs` `env_vars`, Server → **SDK Tuning** → ROCm): when the dist's rocBLAS/hipBLASLt run against the DRIVER's System32 `amdhip64_7.dll`, the **second** 16-bit GEMM in a process fails at kernel launch and llama-server aborts on the first prefill batch. The root cause is the runtime mix, not hipBLASLt: with the dist's own runtime beside the exe (bundled into `bin\` by `03-package.ps1`) every dist passes under default routing, so an installed tree needs no knob; a build from source still runs the driver's runtime. `ROCBLAS_USE_HIPBLASLT=0` (Tensile) is the full-speed fallback. It rides the **environment** (rocBLAS reads it below llama.cpp; hence `env_vars`, not `server_args`) and is a **tri-state** defaulting to *unset*, since hipBLASLt is the faster path where it works: `Some(false)` and `None` are opposite instructions. rocBLAS parses an int: export `"1"`/`"0"`, never `"true"`/`"false"`. An upstream "fixed in X" proves nothing unless it says which runtime the test loaded. Upstream: llama.cpp #25836, TheRock #7271.
- **`split-mode tensor` across a CUDA and a ROCm device ABORTS at load, and the cure is an env var** (`server_cfg.rs` `cuda_allreduce` → `runstate.rs` `env_vars`, Server → **SDK Tuning** → Tensor-split AllReduce; `gpu_split::mixes_cuda_and_rocm` feeds the Models tab's mode strip): ggml-cuda and ggml-hip are one source and declare ONE backend guid, so each backend's `ggml_backend_is_cuda` accepts the other's device, the direct AllReduce comes up over the mixed pair and the first reduction dies with `ROCm error: invalid argument` (v0.6.0, under the default and under `internal` alike). `GGML_CUDA_ALLREDUCE=none` hands the reduction to the meta backend's generic path and the model loads (on an R9700 + RTX 4070 Super: half the layer split's prefill, the same decode). One variable for BOTH backends, server-wide, inert outside tensor mode; an unknown value is run as `none` behind a warning, hence the closed list (`ALLREDUCE_MODES`, mirrored by `Options.allreduce_modes`, e2e-asserted). `nccl` means RCCL on ROCm (linked by the Linux build only) and NCCL on CUDA. Re-check the guid clash on a llama.cpp bump: when upstream fixes it the strip's clause and the hint's last paragraph go.
- **The speculative widgets are DISABLED, not cleared, so a dead `spec-type` survives invisibly and kills the model** (`presets.rs` `prune_inactive_draft_keys`, `form.rs` `prune_inactive_draft_fields`, clone boundary in `gui\models_tab.rs`): the speculative controls are `enabled: draft_active` (`state.slint`), greyed out (never blanked) when the model embeds no MTP heads and no draft file is picked, so a value arriving from elsewhere is written straight back by `form_to_preset`. Spec type is the exception: it stays enabled, offering only `none` and the `ngram-*` types without a draft (they draft from the context), and the prune keeps those entries of the list (`presets::spec_type_is_draftless`); a `draft-*` entry the combo cannot show reads as `none` until the prune removes it. Ways in: **Clone** copies every field onto a different model (`..base.clone()`, straight to disk), and re-pointing a preset at another model keeps the old keys. `spec-type = draft-mtp` on a model without nextn layers makes `llama_init_from_model` return nullptr (`context type MTP requested but model doesn't contain MTP layers`) and **the model fails to load**. Hence the prune runs where the model becomes known (`update_model_info`, leaving the preset dirty so Save is reachable) and where a preset reaches disk without a form (clone, save), gated on having actually READ the GGUF. The verdict is per-FILE (`nextn_predict_layers` in the header), as upstream reads it for every arch (the holdout, granite-switch, is refused with the same log line).
- **The flag that can save a 17-minute prefill rides the ROUTER's command line, and reaches the children by its flag name** (`slot_state.rs` module header, `runstate.rs` `server_args`, Server tab → **Conversation snapshots**): prompt reading is QUADRATIC and the KV cache is process memory, so every restart re-reads the whole conversation (a 234k-token prompt: ~17 minutes, against ~8.3 GiB of sequential IO through `/slots/{id}?action=save|restore`). Those endpoints exist only under `--slot-save-path`. It does reach the router's children: `get_map_key_opt` (`common/preset.cpp`) maps options by FLAG NAME as well as env name, so the router's argv becomes `base_preset` and `preset.merge` copies it onto every model (`unset_reserved_args` does not prune it). It had no `LLAMA_ARG_*` name before v0.7.0 (`LLAMA_ARG_SLOT_SAVE_PATH`, #30272), which is why the framework never relied on one. Since v0.7.0 the dump also carries the context checkpoints (#26004) and the draft state (#30574), so it outgrows the KV-only figures above. The directory must EXIST before launch (validated while PARSING the flag; a missing folder stops the server), so `start()` creates it and the flag is emitted only when the toggle is on. The restore is useful only because `SERVER_TASK_TYPE_SLOT_RESTORE` also restores `slot->prompt.tokens`, which `get_common_prefix` compares against.
- **`llama-bench` takes no prompt and no temperature, and a comma in its flags means SEPARATE benchmarks** (`bench.rs` module header + `synthetic_argv` / `synthetic_sweeps`, the Benchmark tab's **synthetic** engine): `-p` is a token COUNT and it never samples (a stronger reproducibility guarantee, hence a second engine). INI translation: `device` and `tensor-split` are `,` in `presets.ini` and `/` for llama-bench; `override-tensor` is `,` in the INI and `;` there (llama-bench splits `-ot` on `,` into configuration GROUPS first), so `54,12` would silently become two benchmarks. llama-bench runs the CARTESIAN product and `-d` multiplies pp tests too, so prefill and decode are separate invocations (6 tests instead of 12). It cannot model the speculative drafter (`tg` reads ~HALF the live rate with MTP on), the mmproj, the chat template, `--ctx-size` or `--parallel`; `bench::caveats` prints that list under Run and in the saved report.
- **The two benchmark engines demand OPPOSITE llama-server states, and the live one must disable the prefix cache** (`bench\exec.rs` module header, `bench::live_body`): live needs the server up; synthetic needs it DOWN (a second resident copy spills into shared memory over PCIe and reads as a backend regression), so the tab stops it via `gui::stop_server_async_with` (never a bare `runstate::stop`: that path also writes the conversation snapshot and keeps footer, tray and the run-status generation counter in step, or the next tick reports the stop as "no longer running" in red). Live sends `cache_prompt: false` (otherwise repetitions hit the prefix cache and the mean is fiction); `timings.cache_n` is read back as a row note. The request streams with `timings_per_token` (`bench::parse_stream`) so decode splits at the reasoning/answer boundary (thinking drafts poorly, answers well, so one mean describes neither); the jsonl keeps both phases plus a 64-token trace per repetition. Upstream ask: ggml-org/llama.cpp#29372 (a `reasoning` object in `timings`); if it lands, read it instead of streaming. Each preset is committed to bench.db as it finishes (a TDR at the third preset must not lose the first two); a failed preset is dropped and its error carries the engine's last lines. So comparisons can be FALSIFIED: llama-bench's row is kept **verbatim** beside the aggregated point; the resolved **flash-attn is read back** and a disagreement between compared presets is warned ABOVE the table (`auto` resolves per BACKEND; the tab does not pin it); an **environment block** records boot time, each adapter's driver version and every device id's NAME (ids are not stable across driver states). Legs are NOT interleaved, so thermal drift lands on whichever ran last: re-run in reversed order when a difference is small.
- **Hugging Face downloads run OUTSIDE the dialog, never disturb the editor, and the token never enters the UI unless typed** (`gui\downloads.rs` and `gui\hf_dialog.rs` module headers): Download closes the modal at once, so nothing runs in it and Esc always closes it (the old "refuses to close while a download runs" rule is gone with the transfer it protected). What replaced it: the Downloads window's per-row **Cancel download**, which CLOSES the child's stdin and must never send the router's exit line mid-transfer, because on that line llama.cpp deletes its `.downloadInProgress` partial, while EOF leaves it for a Resume (`hf::cancel_stop`, pinned by a test); closing that window only hides it; one download per repository at a time (`Downloads::busy_with`, case-insensitive: two would write one staging folder), other repositories run side by side; a landed download saves its preset and reloads the list but NEVER selects it or touches the form (the editor may hold an unsaved edit): only the row's Show preset does, through `invoke_select_preset` and so the discard guard, and it is refused while a modal is open; the tray's Quit with a download running asks in the Downloads window (`downloads::request_quit`), and a confirmed Quit cancels each by EOF and quits when the last lands (15 s at most). Do not make anything cancel silently, and do not auto-select a finished preset. An EMPTY token field means `hf::token_from_env()`, read at request time; never prefill the field with it, and never format a `Token` into a status line (`Token` has no `Display` on purpose). The worker results land through `invoke_from_event_loop`, whose closure must be `Send`, so they reach `gui::State` through the module's thread-local `STATE`, set by `wire`: a new dialog result that needs `State` goes the same way, not through a captured `Rc`.
- **The live benchmark's prompt is a FILE** (`bench.rs` module header + `normalize_prompt` / `ensure_prompt_file` / `prompt_report_rows`, `gui\bench_tab.rs`, `settings.rs` `BenchPromptFile`): the tab carries a PATH, never a text, so the Run button and `bench sweep` send the same bytes. **Two** prompts ship compiled in and are **seeded** on first use: `config\bench-prompt.txt` (`DEFAULT_PROMPT`, 230 chars, the default) and `config\bench-prompt-long.txt` (`LONG_PROMPT`, from `assets\`, ~40k tokens). Seeded, not installed, because `bin\` under Program Files is not editable without elevation and upgrades overwrite it; `ensure_prompt_file` only ever CREATES and picks its seed by FILE NAME. The long one exists because a benchmark ranks settings only in the regime it measured (at 40k the ranking moves). It is a FROZEN snapshot, pinned to LF in `.gitattributes`, **never regenerated when the docs it came from change** (see `assets\README.md`). **Edit** opens the system's `.txt` handler (a Slint `TextEdit` is sluggish at a few hundred KB); the readout refreshes within one 5 s tick, gated on `(path, mtime, len)`. `on_bench_run` re-reads the file ITSELF, never the display cache. The report identifies the prompt by path + size + **sha256** (`src\sha256.rs`, hand-rolled to avoid six crates), text embedded only up to 4096 chars; the same three facts go into the jsonl header. `normalize_prompt` strips a leading BOM and folds CRLF, so the digest does NOT match `Get-FileHash` on a CRLF file, which the report says.
